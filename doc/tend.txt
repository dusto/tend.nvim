*tend.txt*    AI chat interface for Neovim via Agent Client Protocol

                            AGENTIC.NVIM

A Chat interface for AI agents in Neovim that works with any provider
supporting the Agent Client Protocol (ACP) -- including Claude, Gemini,
Codex, OpenCode, Cursor Agent, Copilot, Auggie, Mistral Vibe, Cline,
Goose, Kiro, Pi, and more.

INTRODUCTION                                      *tend-introduction*

                                                           *tend.nvim*

Tend.nvim brings your AI assistant to Neovim through the Agent Client
Protocol (ACP). You get the same results and performance as the provider's
official CLI directly from the terminal.

Tend.nvim is the interface; your agent is the brain. The plugin uses
your existing terminal configurations and authentication methods --
including MCP servers, commands, skills, and sub-agents.

Sessions are interchangeable: start a conversation in Neovim and continue
it in the terminal, or pick up a terminal session inside Neovim. Your ACP
provider manages sessions natively, so they are available everywhere.

There are no hidden prompts or magic behind the scenes -- just a chat
interface, your colors, and your keymaps.

Supported providers:
  - Claude (claude-agent-acp)
  - Gemini (gemini-acp)
  - Codex (codex-acp)
  - OpenCode (opencode-acp)
  - Cursor Agent (cursor-acp)
  - Copilot (copilot-acp)
  - Augment (auggie-acp)
  - Mistral Vibe (mistral-vibe-acp)
  - Cline (cline-acp)
  - Goose (goose-acp)
  - Kiro (kiro-acp)
  - Pi (pi-acp)
  - ...and any future ACP-compatible provider

REQUIREMENTS                                      *tend-requirements*

- Neovim v0.11.0 or higher
- An ACP provider CLI (must be in PATH or an absolute path)

For security reasons, this plugin does not install or manage binaries.
You must install the CLI for your chosen provider manually. Global
install is recommended (especially with `pnpm`, which uses a stable
global path), but any method that puts the binary in PATH works.

Pin your versions! See the security note below each provider.

INSTALLATION                                      *tend-installation*

                                                       *tend.setup()*

Using lazy.nvim: ~
>lua
  {
    "dusto/tend.nvim",

    --- @type tend.PartialUserConfig
    opts = {
      -- Providers are owned by the daemon (tendd). Seed the ids offered
      -- by :TendProvider; the live set comes from the daemon's provider
      -- list. See |tend-config-daemon|.
      daemon = { providers = { "claude-agent-acp", "codex-acp" } },
    },

    -- The chat widget lifecycle is the require("tend") Lua API (see
    -- |tend-usage|). Sessions, tasks, and approvals are the :Tend* commands
    -- (see |tend-daemon|): :TendConnect, :TendSessionNew, :TendChat, ...
    keys = {
      {
        "<C-\\>",
        function() require("tend").toggle() end,
        mode = { "n", "v", "i" },
        desc = "Toggle Tend Chat",
      },
    },
  }
<

CONFIGURATION                                    *tend-configuration*

The full default configuration with all options is defined in
`lua/tend/config_default.lua`. You only need to specify the options
you want to override.

  Providers are owned by the daemon (tendd), not this plugin: the
  provider CLIs, per-provider spawn config, and session defaults live
  in the daemon's configuration. The plugin only seeds the id list
  offered by |:TendProvider| via `daemon.providers` (see
  |tend-config-daemon|); the live set comes from the daemon's provider
  list. Session mode / model / thought level are switched at runtime
  from the chat widget (see |tend-keymaps|).

                                          *tend-config-windows*
windows ~
  Type: `table`

  Configure window layout and dimensions.

  `position`           Position of the sidebar: `"right"`, `"left"`,
                       or `"bottom"`. Default: `"right"`.
  `width`              Width of the sidebar. String percentage or
                       number. Default: `"40%"`.
  `height`             Height when position is `"bottom"`. String
                       percentage or number. Default: `"30%"`.
  `stack_width_ratio`  Ratio for stacked panels. Default: `0.4`.

  Sub-panel options (each accepts `win_opts` table):

  `chat.win_opts`          Window options for the chat panel.
  `input.height`           Prompt input height. Default: `10`.
  `code.max_height`        Code block max height. Default: `15`.
  `files.max_height`       File list max height. Default: `10`.
  `diagnostics.max_height` Diagnostics max height. Default: `10`.
  `todos.display`          Show todos panel. Default: `true`.
  `todos.max_height`       Todos max height. Default: `10`.

                                          *tend-config-settings*
settings ~
  Type: `table`

  `move_cursor_to_chat_on_submit`  Automatically move cursor to chat
                       window after submitting a prompt.
                       Default: `true`.

                                          *tend-config-daemon*
daemon ~
  Type: `table`

  Settings for the daemon-client commands. See |tend-daemon|.

  `socket`        Path of the `tendd` Unix socket. Default: the daemon's
                  well-known path (`$XDG_RUNTIME_DIR/tend/tend.sock`).
  `providers`     ACP provider ids offered by |:TendProvider|.
                  Default: `{}`.
  `assignee`      Task assignee used by |:TendClaim|.
                  Default: `$USER`.
  `persona_dirs`  User-scoped directories |:TendPersona| scans for `*.md`
                  personas.
                  Default: `$XDG_CONFIG_HOME/tend/personas`, falling back
                  to `~/.config/tend/personas`.
  `persona_sources`
                  Harness agent dirs imported by |:TendPersona|, as a list
                  of `{ source = <id>, dir = <workspace-relative dir> }`.
                  Default: claude (`.claude/agents`) and opencode
                  (`.opencode/agent`).

                                          *tend-config-hooks*
hooks ~
  Type: `table`

  Callbacks for chat lifecycle events. See |tend-hooks|.

                                          *tend-config-headers*
headers ~
  Type: `table`

  Customize window headers for each panel. Each header can be a
  table with `title` and `suffix` fields, or a function that receives
  header parts and returns a custom string.

>lua
  --- @type tend.PartialUserConfig
  opts = {
    headers = {
      chat = {
        title = "My Chat",
        suffix = "",
      },
      input = function(parts)
        return parts.title .. " | custom"
      end,
    },
  }

USAGE                                                    *tend-usage*

The `require("tend")` functions below cover the chat widget lifecycle,
editor-context attach, and a few session actions (stop, provider, reattach)
as convenience entry points for keymaps. Sessions themselves are owned by the
daemon; starting, prompting, delegating tasks, approvals, and diff review are
the `:Tend*` commands under |tend-daemon|. These functions act on the daemon's
focused session; they report (they do not auto-create a session) when none is
focused — start one with |:TendSessionNew|.

The context-attach entries below add editor context — files, the current
selection, diagnostics — to the *next* prompt turn for the focused session.
The daemon receives them as agent.prompt content blocks (files as resource
links, images inline); each turn consumes and clears whatever was attached.

                                                      *tend.toggle()*
tend.toggle({opts})
  Toggle the chat widget on the focused session.

  Parameters: ~
    {opts}  (table|nil)  Optional fields:
      `focus_prompt`  (boolean)  Move cursor to prompt. Default: `true`.

                                                        *tend.open()*
tend.open({opts})
  Open the chat widget on the focused session. Keeps it open if already
  visible. Accepts the same {opts} as |tend.toggle()|.

                                                       *tend.close()*
tend.close()
  Close the chat widget.

                                              *tend.rotate_layout()*
tend.rotate_layout({layouts})
  Rotate through window positions (right -> bottom -> left).

  Parameters: ~
    {layouts}  (table|nil)  List of position strings. Default:
                            `{ "right", "bottom", "left" }`.

                                               *tend.add_selection()*
tend.add_selection()
  Add the current visual selection to the next turn's context (a no-op in
  normal mode).

                                                    *tend.add_file()*
tend.add_file()
  Add the current file (buffer) to the next turn's context.

                                         *tend.add_files_to_context()*
tend.add_files_to_context({opts})
  Add a list of file paths and/or buffer numbers to the next turn's
  context.

  Parameters: ~
    {opts}  (table)  Required field:
      `files`  (table)  List of file paths (strings) or buffer numbers
                        (integers).

>lua
  require("tend").add_files_to_context({
    files = { "src/main.lua", "src/utils.lua" },
  })
<

                                 *tend.add_selection_or_file_to_context()*
tend.add_selection_or_file_to_context()
  Add the visual selection when in visual mode, else the current file.

                                   *tend.add_current_line_diagnostics()*
tend.add_current_line_diagnostics()
  Add diagnostics at the current cursor line to the next turn's context;
  reports when the line has none.

                                       *tend.add_buffer_diagnostics()*
tend.add_buffer_diagnostics()
  Add all diagnostics from the current buffer to the next turn's context;
  reports when the buffer has none.

                                             *tend.stop_generation()*
tend.stop_generation()
  Cancel the in-flight turn on the focused session, returning it to idle.
  Safe when no turn is running.

                                             *tend.switch_provider()*
tend.switch_provider()
  Pick the provider used for new sessions. The daemon binds a provider at
  session start, so this sets the default for the next session rather than
  switching a running session's provider. Equivalent to |:TendProvider|.

                                             *tend.restore_session()*
tend.restore_session()
  Reattach to a running daemon session: lists them and focuses the chosen
  one. Equivalent to |:TendSessionAttach|.

                                          *tend.restore_session_by_id()*
tend.restore_session_by_id({session_id})
  Reattach to a specific running daemon session by id.

  Parameters: ~
    {session_id}  (string)  The session id to focus.

KEYMAPS                                                *tend-keymaps*

These keybindings are automatically set in Tend buffers:

  Key                    Mode    Description ~
  <S-Tab>                n/v/i   Switch the focused session's behavior/
                                 permission mode (daemon-advertised;
                                 reports if none)
  <CR>                   n       Submit prompt
  <C-s>                  n/v/i   Submit prompt
  <Tab>                  i       Accept file completion
  <localLeader>f         n       Pick a workspace file (vim.ui.select);
                                 inserts @path and attaches it
  <localLeader>p         n       Paste image from clipboard
  <C-v>                  i       Paste image from clipboard
  <localLeader>s         n       Pick the ACP provider for new sessions
                                 (daemon provider list)
  <localLeader>S         n       Switch the focused daemon session
  <localLeader>m         n       Switch the focused session's model
                                 (daemon-advertised; reports if none)
  <localLeader>t         n       Switch the focused session's thought/
                                 reasoning level (daemon thought-level
                                 axis; reports if none)
  q                      n       Close chat widget
  d                      n/v     Remove file/selection/diagnostic
  ]]                     n       Next chat heading
  [[                     n       Previous chat heading
  ]t                     n       Next tool call
  [t                     n       Previous tool call
  ]c                     n       Next diff hunk
  [c                     n       Previous diff hunk

Permission keymaps (active while a permission request is pending):

  Key                        Mode    Description ~
  <C-n>                      n       Cycle to next pending permission block
  <C-p>                      n       Cycle to previous pending permission block
  h / <Left> / k / <Up>      n       Focus previous permission button
  l / <Right> / j / <Down>   n       Focus next permission button
  <CR>                       n       Submit focused permission button
  1..4                       n       Submit permission option directly

                                        *tend-keymaps-customizing*
Customizing keymaps ~

Override default keybindings via the `keymaps` config option:
>lua
  --- @type tend.PartialUserConfig
  opts = {
    keymaps = {
      widget = {
        close = "q",
        change_mode = {
          { "<S-Tab>", mode = { "i", "n", "v" } },
        },
        switch_provider = "<localLeader>s",
        switch_session = "<localLeader>S",
        switch_model = "<localLeader>m",
        change_thought_level = "<localLeader>t",
      },
      prompt = {
        submit = {
          "<CR>",
          { "<C-s>", mode = { "n", "v", "i" } },
        },
        paste_image = {
          { "<localLeader>p", mode = { "n" } },
          { "<C-v>", mode = { "i" } },
        },
        accept_completion = {
          { "<Tab>", mode = { "i" } },
        },
        pick_file = "<localLeader>f",
      },
      chat = {
        next_heading = "]]",
        prev_heading = "[[",
        next_tool_call = "]t",
        prev_tool_call = "[t",
      },
      diff_preview = {
        next_hunk = "]c",
        prev_hunk = "[c",
      },
      permission = {
        cycle_next = "<C-n>",
        cycle_prev = "<C-p>",
      },
    },
  }
<

The per-block permission keys (`h`, `l`, `j`, `k`, `<Left>`, `<Right>`,
`<Up>`, `<Down>`, `<CR>`, `1`..`4`) are fixed and not configurable. Only
`cycle_next` / `cycle_prev` can be remapped via `keymaps.permission`.

Keymap configuration formats:
  - String: `close = "q"` (normal mode by default)
  - Array: `submit = { "<CR>", "<C-s>" }` (multiple bindings)
  - Table with mode: `{ "<C-s>", mode = { "i", "v" } }`

DIFF PREVIEW                                      *tend-diff-preview*

When the agent makes file edits, tend.nvim shows a preview of the
changes before you accept or reject them.

                                        *tend-config-diff-preview*
Configuration: ~
>lua
  --- @type tend.PartialUserConfig
  opts = {
    diff_preview = {
      enabled = true,
      layout = "split",  -- "split" or "inline"
      center_on_navigate_hunks = true,
    },
  }
<

  `enabled`                    Enable diff preview. Default: `true`.
  `layout`                     `"split"` (side-by-side) or `"inline"`
                               (unified). Default: `"split"`.
  `center_on_navigate_hunks`   Center view on hunk navigation.
                               Default: `true`.

Navigation: use `]c` / `[c` to move between hunks (configurable
via |tend-keymaps-customizing|).

Note: changing layout requires restarting Neovim.

DIFF REVIEW                                        *tend-diff-review*

Read-only review of a daemon change set — |:TendDiff| and the daemon's
`editor.diff` request — renders through a configurable backend. The daemon
carries the full before/after snapshots, so review never reads disk or
reconstructs a file (a denied or still-pending proposal is shown exactly as
proposed).

                                        *tend-config-diff-review*
Configuration: ~
>lua
  --- @type tend.PartialUserConfig
  opts = {
    diff_review = {
      backend = "native",  -- "native" | "mini_diff" | "custom"
      style = "split",     -- native only: "split" | "unified"
      renderer = nil,      -- required for the "custom" backend
    },
  }
<

  `backend`    Renderer backend. Default: `"native"`.
               - `"native"`: built-in, no dependencies.
               - `"mini_diff"`: overlay the snapshots via mini.diff; falls
                 back to native when mini.diff is not installed.
               - `"custom"`: route to `renderer` (see below); falls back to
                 native when `renderer` is not a function.
  `style`      Native layout: `"split"` (two side-by-side diff buffers) or
               `"unified"` (one `diff`-filetype buffer). Default: `"split"`.
  `renderer`   For `backend = "custom"`: a function called as
               `renderer(change_set_id, files)`, where each file is a table
               `{ uri, before, after }`. It owns the display; the return
               value is passed back to the caller unchanged.

Any backend receiving self-contained snapshots keeps the read-only review
semantics — a plugin or callback must not reconstruct the file from disk.

                                       *tend-permission-approval*
Permission approval ~

When a tool call requires permission, the chat buffer shows approval
buttons. Press the corresponding number key for quick responses:
  1 = allow once, 2 = allow always, 3 = reject once, 4 = reject always.

FEATURES                                              *tend-features*

Slash commands ~
                                                *tend-slash-commands*
Type `/` in the prompt buffer to see available slash commands with
auto-completion. The `/new` command is always available. Other
commands are provided by your ACP provider.

File picker ~
                                                  *tend-file-picker*
Type `@` in the prompt to trigger native Neovim completion with
workspace files (accept with `<Tab>`). A picked file is attached to
the next prompt turn's context — the same content block as
|tend.add_file()| — so the agent receives the file, not just the
`@path` text. Reference multiple files:
`@file1.lua @file2.lua`. Uses `rg`, `fd`, `git ls-files`, or Lua globs
as fallback.

Alternatively, press `<localLeader>f` in the prompt to open the file
list through `vim.ui.select` — so your own picker (telescope, fzf-lua,
snacks, mini.pick, dressing, ...) is used — then the chosen `@path` is
inserted and attached the same way. Configurable via
`keymaps.prompt.pick_file`.

Image and screenshot support ~
                                                     *tend-images*
Drag-and-drop images into the prompt buffer or paste from clipboard.
Drag-and-drop works with any terminal that supports it.
In SSH/headless sessions, image paste and drag-and-drop
usually do not reach remote Neovim.
Tend does not copy local files into the remote filesystem.
Upload the image first with `scp`, `SFTP`, or your usual file-transfer
workflow, then attach the remote file path using the `@` file picker.

Clipboard paste uses native OS tooling:

  - macOS: works out of the box (uses `osascript`).
  - Windows: works out of the box (uses bundled `powershell.exe`).
  - WSL: works out of the box when Windows interop and `wslpath` are
    available.
  - Linux (Wayland): install `wl-clipboard` (provides `wl-paste`).
    - Debian/Ubuntu: `sudo apt install wl-clipboard`
    - Arch:          `sudo pacman -S wl-clipboard`
    - Fedora:        `sudo dnf install wl-clipboard`
  - Linux (X11): install `xclip`.
    - Debian/Ubuntu: `sudo apt install xclip`
    - Arch:          `sudo pacman -S xclip`
    - Fedora:        `sudo dnf install xclip`

Then press `<localleader>p` in the Prompt buffer to paste the image.

Session restoration ~
                                            *tend-session-restore*
Reattach to a session the daemon is running with |:TendSessionAttach|
(see |tend-daemon|), which lists the daemon's active sessions and
focuses the one you pick. Restoring an earlier, non-running session
from the provider is not yet wired on the daemon path.

System information ~
                                             *tend-system-context*
The first message of each session automatically includes platform
info, shell/Neovim version, date, git status, and project root.
This reduces time to first response by providing immediate context.

Event hooks ~
                                                     *tend-hooks*
>lua
  --- @type tend.PartialUserConfig
  opts = {
    hooks = {
      on_create_session_response = function(data)
        -- Fires on both success and failure. Check `data.err` first.
        -- data.session_id: string|nil (nil if err is set)
        -- data.tab_page_id: number (may be invalid if tab was closed;
        --   guard with vim.api.nvim_tabpage_is_valid before use)
        -- data.response: table|nil (nil if err is set)
        -- data.err: table|nil (nil on success)
      end,
      on_prompt_submit = function(data)
        -- data.prompt: string
        -- data.session_id: string
        -- data.tab_page_id: number
      end,
      on_response_complete = function(data)
        -- data.session_id: string
        -- data.tab_page_id: number
        -- data.success: boolean
        -- data.error: table|nil
      end,
      on_session_update = function(data)
        -- data.session_id: string
        -- data.tab_page_id: number
        -- data.update: table
      end,
      on_file_edit = function(data)
        -- data.filepath: string (absolute path)
        -- data.session_id: string
        -- data.tab_page_id: number
        -- data.bufnr: number|nil (if file is loaded in a buffer)
      end,
      on_request_permission = function(data)
        -- data.request: table (contains .toolCall)
        -- data.session_id: string
        -- data.tab_page_id: number
      end,
    },
  }
<
Note: mutating the file inside `on_file_edit` (for example
formatters that save) may cause the agent to re-read or retry
edits on its next action. Prefer agent-side validation via
CLAUDE.md / AGENTS.md when possible.

                                                *tend-highlight-groups*
Highlight groups ~

Tend.nvim defines custom highlight groups you can override to
match your colorscheme. If a group already exists when the plugin
loads, that definition is preserved.

  Group                    Purpose                    Default ~
  `TendDiffDelete`        Deleted lines in diff      Links to DiffDelete
  `TendDiffAdd`           Added lines in diff        Links to DiffAdd

DAEMON (PREVIEW)                                          *tend-daemon*

The plugin is moving to a daemon-client architecture: a `tendd` daemon owns
ACP providers, task-scoped sessions, the event bus, and approvals; the
plugin is one client over a Unix socket. These commands drive that flow.
They are independent of the chat sidebar above and require a running
`tendd`. Configure them via |tend-config-daemon|.

The plugin pins minimum daemon API versions per method set and checks the
daemon's reported versions during the connect handshake. On a mismatch the
connection reports an error and stops (no reconnect loop) — upgrade `tendd`
or the plugin, then run |:TendConnect| again. The pinned minimums, the
connection state, and the daemon's versions are reported under the
"Daemon (tendd)" section of `:checkhealth tend`.

Sessions and tasks are separate. A session is a conversation with an
agent; a task is work authorization. Start a session with |:TendSessionNew|
and chat with it freely — the daemon refuses file or command changes until
a task is delegated to the session (see |:TendTaskPick|).

                                                          *:TendConnect*
:TendConnect
  Connect to the daemon (and keep reconnecting) and open the workspace
  containing the current working directory. Run this first.

                                                          *:TendTaskNew*
:TendTaskNew
  Prompt for a title, create a task in the workspace's task provider, and
  make it the current task.

                                                          *:TendTaskPick*
:TendTaskPick
  Pick a task from the workspace's task list and delegate it: choose a
  target — a new session or a running one — and the task is handed to that
  session as a prompt turn. The target becomes the focused session (see
  |:TendSessionAttach|) for follow-up |:TendChat|. "New session" is always
  offered, so this works even with no sessions running.

                                                          *:TendClaim*
:TendClaim
  Claim the current task for `daemon.assignee` and mark it in progress.

                                                          *:TendProvider*
:TendProvider
  Pick the ACP provider (from `daemon.providers`) used as the default for
  new sessions.

                                                          *:TendPersona*
:TendPersona
  Pick a persona. Lists native definitions — `daemon.persona_dirs` plus
  the workspace's `.tend/personas/` — alongside agents imported read-only
  from harness dirs in the workspace (`daemon.persona_sources`, e.g.
  `.claude/agents/`). Imported ids are namespaced by source
  (`claude:reviewer`); on a name collision, workspace personas shadow
  imported agents, which shadow user personas.

                                                        *:TendSessionNew*
:TendSessionNew
  Pick a configured provider and start a task-less session on the open
  workspace, then focus it. The session converses immediately via
  |:TendChat|; the daemon keeps file and command changes gated until a task
  is delegated to it with |:TendTaskPick|. The session's events render into
  a transcript buffer; its approval prompts surface as floats.

                                                     *:TendSessionAttach*
:TendSessionAttach
  List the daemon's active sessions — each with its provider, task, and
  status (idle/running/waiting_approval/...) — and focus the one you pick.
  Focusing follows the session's event stream (transcript) and makes
  |:TendChat| and |:TendEvents| target it. The currently focused session
  is marked. A session started in this editor stays tracked; selecting it
  again reuses its transcript.

  The same picker is reachable from inside the chat widget via the
  `switch_session` keymap (default `<localLeader>S`, see
  |tend-keymaps|), so you can switch which session the chat shows and
  targets without leaving it. Each session keeps its own transcript
  buffer, so switching is instant and preserves scrollback.

                                                 *:TendSessionDisconnect*
:TendSessionDisconnect
  Stop following a session in this editor: pick a tracked session and
  detach from it — its event stream is unsubscribed and its transcript
  dropped. The session keeps running on the daemon (this is a client-side
  detach, not a stop), so |:TendSessionAttach| can pick it up again.

                                                          *:TendChat*
:TendChat
  Open (or focus) the chat widget on the focused session, cursor in the
  prompt input. Typing and submitting drives the agent; replies stream into
  the same window — messages, thinking blocks, and tool-call blocks — so
  prompting and reading happen in one place. One widget is shared across
  sessions: it shows whichever session is focused, so |:TendSessionAttach|
  switches which conversation the widget displays. A session's approval
  requests surface as a float resolved in place (see |:TendApprove|).

                                                     *tend-daemon-slash*
Slash commands (prompt) ~

  Typing `/` at the start of the chat prompt completes slash commands for the
  focused session. The command set is the daemon's merged list: the agent's
  own advertised commands plus the built-in daemon/harness commands (task
  actions). Command names complete locally from that set; a command's first
  argument (e.g. a task id) completes live from the daemon as you type it.

  Completion is native (`completefunc`) — no LSP and no extra plugin. It
  triggers automatically on `/`; there is nothing to configure.

  Submitting a `/command args` line invokes it for the focused session. The
  daemon dispatches: a command it owns runs as a daemon action (its outcome
  is reported), and anything else is forwarded to the agent as a prompt turn
  (its output streams into the transcript like a normal message).

                                                          *:TendEvents*
:TendEvents
  Open (or focus) the chat widget on the focused session with the cursor in
  the transcript rather than the input — for reading back the conversation.

                                                          *:TendApprove*
:TendApprove
  Re-list pending approvals and open the approval float; reports when
  nothing is pending. Approvals also surface on their own when the daemon
  raises them.

                                                      *:TendOpenChanges*
:TendOpenChanges [{change_set_id}]
  Open a change set's files in buffers for in-place review. With no
  argument you are prompted for the id. Read-only — opens nothing else
  and changes nothing.

                                                          *:TendDiff*
:TendDiff [{change_set_id}]
  Review a change set's captured before/after snapshots, one tab per file,
  through the configured diff backend (see |tend-diff-review|). The daemon
  serves the snapshots (a denied or still-pending proposal is reviewable
  exactly as proposed), so this shows what the set changed, not the live
  file. With no argument you are prompted for the id. Read-only.

The daemon may also drive these directly: when it has a change set to
show it calls `editor.open` / `editor.diff` on the bound editor, which
the plugin renders the same way.
